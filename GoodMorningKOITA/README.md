# GoodMorningKOITA

등록한 키워드로 네이버 뉴스에서 날짜 기준(기본: 어제 0시부터)으로 기사를 모아 보여주고, 체크한 기사를 엑셀로 내려받거나 별도 기사 DB(`database` 폴더)에 계속 쌓아 가는 웹 프로그램입니다. 버전과 바뀐 내용은 `VERSION`, `CHANGELOG.md`에 있습니다.

## 실행 (Windows)

1. Python 3.10 이상이 설치되어 있어야 합니다.
2. 이 폴더를 PC로 복사한 뒤 `run.bat`을 더블클릭합니다.
   - 처음 한 번은 필요한 라이브러리를 설치하느라 1~2분 걸립니다.
3. 브라우저에서 http://127.0.0.1:8000 이 자동으로 열립니다.

네이버 API 키는 `.env` 파일에 들어 있습니다. NAVER API HUB(네이버 클라우드 플랫폼 콘솔)의 Application 인증 정보(Client ID / Client Secret)를 넣으면 되고, 키를 바꾸면 이 파일만 고치면 됩니다.

## 폰·PC에 앱으로 설치 (v1.3.0~)

서버를 클라우드에 올려 두면 PC가 꺼져 있어도 폰과 PC에서 같은 화면을 쓸 수 있습니다.

- **안드로이드**: 크롬으로 서버 주소를 열고 메뉴 → "홈 화면에 추가"(또는 "앱 설치").
- **PC**: 크롬·엣지 주소창 오른쪽의 설치 아이콘(⊕)을 누르면 별도 앱 창으로 열립니다.
- 앱 설치는 `https://` 주소(또는 내 PC의 `127.0.0.1`)에서만 됩니다.

**Oracle Cloud 무료 서버에 올리는 방법은 [deploy/README.md](deploy/README.md)에 단계별로 있습니다** (설치 스크립트 한 줄, HTTPS 자동, 구글 드라이브 자동 백업).

### 클라우드 서버에서 실행 (Docker)

```
docker build -t goodmorningkoita .
docker run -d --restart unless-stopped -p 8000:8000 -v koita-data:/data --env-file .env goodmorningkoita
```

클라우드에 올릴 때 `.env`에 꼭 넣을 것: `APP_PASSWORD`(로그인 비밀번호), `SESSION_SECRET`(아무 긴 문자열). 이미지 안에서는 `DATA_DIR=/data`, `HOST=0.0.0.0`이 기본이라 검색 결과와 기사 DB가 `/data` 디스크에 남습니다.

서버가 살아 있는지는 로그인 없이 `GET /healthz`로 확인합니다 (`{"ok": true, "version": "1.3.0"}`, 문제가 있으면 HTTP 503).

### 설정값 (`.env`, 모두 선택)

| 이름 | 기본값 | 내용 |
|---|---|---|
| `APP_PASSWORD` | 없음(로그인 없음) | 넣으면 모든 화면·API에 로그인 필요 |
| `SESSION_SECRET` | 켤 때마다 새로 만듦 | 넣으면 서버를 다시 켜도 로그인 유지 |
| `DATA_DIR` | 프로그램 폴더 | `news.db`와 `database` 폴더를 둘 곳 |
| `ARCHIVE_DIR` | `DATA_DIR/database` | 기사 DB 폴더만 따로 지정 |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | 서버 주소·포트 |
| `OPEN_BROWSER` | 켬 | `0`이면 실행할 때 브라우저를 열지 않음 |
| `NEWSPAPER_DIR` | 없음 | 지면보도 날짜 확인에 쓸 지면 기사 파일 폴더 |

## 화면에서 할 수 있는 일

- **첫 화면을 열면** 켜져 있는 키워드로 어제 0시부터의 기사를 자동 검색해 목록에 보여주고 DB에 저장합니다.
  (10분 안에 다시 열면 검색을 건너뛰고 저장된 목록만 보여줍니다. 바로 다시 찾으려면 "지금 다시 검색")
- **검색 기간**: "지금 다시 검색" 옆에서 오늘·어제부터(기본)·최근 7일·날짜 지정을 고를 수 있습니다. 모든 기간은 시간이 아니라 날짜(0시) 기준입니다. 예: 10월 26일에 "오늘"은 26일 0시 이후, "어제부터"는 25일 0시 이후, "최근 7일"은 20일 0시 이후. 검색이 끝나면 아래 기사 목록도 같은 기간으로 맞춰집니다.
  - 네이버 API는 키워드당 최신 1,100건까지만 주므로, 아주 긴 기간은 앞쪽 기사가 빠질 수 있습니다(화면에 안내가 뜹니다).
- **키워드**: 기본은 `"한국산업기술진흥협회"`, `"산업기술진흥협회"`, `"산기협"`, `"장영실상"`, `"엔지니어상"` 5개이고, **하나라도 들어간 기사를 모두 모읍니다(OR)**. 여러 키워드에 걸린 기사도 목록에는 한 번만 나오고, 걸린 키워드는 "키워드" 칸에 모두 표시됩니다. 추가, 수정(✎), 잠시 빼기(⏸), 삭제(✕). `"따옴표"`로 감싸면 정확히 일치하는 기사 위주로 검색합니다.
- **골라 보기·정렬**: 기사 목록 위의 "언론사 전체", "키워드 전체" 목록에서 특정 언론사나 키워드를 고르면 그 기사만 보입니다(가나다순, 괄호 안은 건수). 옆의 정렬 목록으로 최신순·오래된순·언론사순·키워드순으로 바꿀 수 있습니다. "목록에서 찾기"와 함께 쓸 수 있고, 전체 체크는 지금 보이는 기사에만 적용됩니다.
- **체크**: 기사 앞 칸을 체크합니다. 표 머리의 칸은 지금 보이는 기사를 한꺼번에 체크/해제합니다.
- **엑셀 다운로드**: 체크한 기사만 기존 스크립트와 같은 형식(연번·날짜·언론사명·구분·제목·URL)으로 내려받습니다.
  - 지면 기사는 지면 행(다음 날짜, URL "-")이 추가되고, 방송사 영상 기사는 방송 행이 추가됩니다.
- **수정**: 언론사명, 지면, 영상 표시가 틀렸으면 표에서 클릭해 고칠 수 있습니다. 고친 값은 DB에 저장됩니다.

- **분류** (v1.3.0~): 기사마다 키워드 옆 "분류" 목록에서 보도자료·특별보도·인용·장영실상·엔지니어상·협력·언급·이슈·정부사업·기타 중 하나를 고릅니다(기본 "선택"). DB 저장을 누르면 기사 DB 맨 오른쪽 "분류" 열에 들어갑니다. 여러 기사를 체크한 뒤 위쪽 "체크한 기사 분류" 목록에서 고르면 한 번에 바뀝니다. 이미 저장된 기사도 분류를 골라 다시 DB 저장하면 새 값으로 바뀝니다.
- **DB 저장**: 체크한 기사를 엑셀과 같은 행 형태로 기사 DB 맨 아래에 이어 붙입니다. 이미 DB에 있는 행은 건너뜁니다(분류만 새로 고른 경우 분류는 바뀜). DB에 들어간 기사는 목록에 "저장됨"이 붙습니다.

## DB 편집 창 (v1.3.0~)

위쪽 **DB 편집** 버튼을 누르면 새 탭에 기사 DB가 엑셀 같은 표로 열립니다.

- 칸을 눌러 바로 고칩니다. 방향키·Enter로 칸 이동, Esc는 그 칸을 원래 값으로, 엑셀에서 여러 칸을 복사해 붙여넣을 수 있습니다.
- 고친 칸은 노란색, 새 행은 연번이 초록색입니다. 행 추가, 왼쪽 칸 체크 후 "체크한 행 삭제"(다시 누르면 취소), "수정 모두 취소".
- **저장**(Ctrl+S)을 누르면 SQLite 원본을 바꾸고 CSV·JSON도 똑같이 다시 만듭니다. 날짜 형식, 빈 칸, URL, 중복 행에 문제가 있으면 저장하지 않고 그 칸을 빨갛게 표시합니다. 연번은 저장할 때 게재일시 최신순으로 다시 매겨집니다.
- 연번·저장일시는 고칠 수 없습니다.

### 붙여넣어 가져오기 (예전 DB 한꺼번에 넣기)

1. 편집 창에서 **붙여넣어 가져오기**를 누릅니다.
2. 예전 DB를 엑셀에서 **머리글 행까지** 복사해 칸에 붙여넣거나, "CSV 파일 열기"로 CSV를 엽니다.
3. 머리글 이름(날짜·언론사명·구분·제목·URL·게재일시·키워드·분류)으로 열을 맞춥니다. 연번 등 다른 열은 무시합니다. 머리글이 없고 6칸이면 엑셀 내보내기 순서(연번·날짜·언론사명·구분·제목·URL)로 읽습니다.
4. 미리보기에서 **추가할 행**, **이미 있음**(온라인·방송은 URL, 지면은 같은 언론사·제목), **형식 오류**(어느 칸이 문제인지)를 확인합니다.
5. "N행을 표에 넣기" → 표 맨 위에 들어간 행(연번 초록색)을 확인하고 **저장**합니다.

게재일시가 없으면 날짜 0시(`2025-01-10T00:00:00+09:00`), 키워드·분류가 없으면 빈 값으로 넣습니다. CSV를 직접 고쳐도 다음 저장 때 SQLite에서 다시 만들어지므로, 예전 DB는 이 방법으로 넣어 주세요.

### 지면보도 날짜 확인

편집 창의 **지면보도 날짜 확인** 버튼은 지면 기사 파일들의 파일명과 DB의 지면 행을 비교합니다.

- 폴더: `.env`의 `NEWSPAPER_DIR` (하위 폴더 포함). 화면에서 바꿔 넣을 수도 있고, 넣은 폴더는 브라우저가 기억합니다.
- 파일명 형식: `[매체명] 기사제목_지면_날짜.jpg` (예: `[매일경제] 산기협 장영실상 시상_A16면_20261027.jpg`). 제목 안에 밑줄(_)이 있어도 되고, 예전 형식 `[매체명]_기사제목_지면_날짜`도 읽습니다. 날짜는 `20261027`, `2026-10-27`, `2026.10.27`, `261027`을 읽습니다.
- 매체명과 제목(띄어쓰기·기호 무시, 잘린 제목 허용)으로 DB 지면 행과 짝을 짓고 날짜·지면 번호를 비교합니다. 지면은 **숫자만** 비교합니다(`인물 29면` = `A29면`). 저장하지 않은 수정도 반영해서 비교합니다.
- 제목이 달라 짝을 못 찾으면, 매체가 같고 날짜가 ±1일 이내이거나 제목에 같은 낱말이 많이 들어간 행을 **일치 의심**으로 보여 줍니다. 의심 이유(매체 같음, 날짜 차이, 겹치는 낱말, 비슷한 정도)와 DB 제목을 보고 맞으면 체크해서 반영합니다(처음엔 체크 안 됨).
- 결과: **틀림**(어느 부분이 파일 값 ↔ DB 값으로 다른지), **일치 의심**, **파일명 오류**(어느 칸을 못 읽었는지), **DB에 없음**, **중복 파일**, **파일 없는 DB 지면 행**.
- **DB에 없음**으로 나온 파일은 두 가지로 처리합니다.
  - **DB 기사와 연결**: 이미 DB에 있는데 제목이 달라 못 찾은 경우. 같은 매체 기사가 날짜 가까운 순으로 나오고(제목·언론사로 찾기도 됨) "이 기사로 연결"을 누르면 됩니다. 지면 행을 고르면 그 행과 날짜·지면을 비교하고, 온라인·방송 행을 고르면 그 기사의 지면 행(파일의 날짜·지면)을 새로 만들어 연결합니다. 연결은 `database/print_links.json`에 기억해 다음 확인 때도 쓰고, "연결 끊기"로 풀 수 있습니다.
  - **새로 등록**: 정말 DB에 없는 경우. 파일명의 매체·제목·지면·날짜로 새 지면 행을 표에 넣습니다(게재일시는 날짜 0시, 분류는 표에서 고르기).
  - 일치 의심·중복 파일도 "다른 행과 연결"로 직접 짝을 바꿀 수 있습니다. 새로 만든 행은 **저장**해야 DB에 들어갑니다.
- 고칠 항목을 체크하고 "체크한 수정을 표에 반영" → 노란 칸을 확인한 뒤 **저장**하면 DB가 고쳐집니다.
- 폰이나 클라우드 서버에서 쓸 때는 "폴더 직접 고르기"로 내 기기의 폴더를 고르면 파일명만 보내서 비교합니다(이미지는 올리지 않음).

## 화면 없이 실행 (AI 에이전트·예약 작업용)

`cli.py`는 결과를 JSON으로 출력하고 종료 코드로 상태를 알려 줍니다 (0 정상, 1 확인할 문제 있음, 2 실행 오류). 설정은 `.env`를 그대로 씁니다.

```
.venv\Scripts\python cli.py print-check                 # NEWSPAPER_DIR 폴더와 비교
.venv\Scripts\python cli.py print-check --folder D:\지면 --apply   # 틀린 날짜·지면을 DB에 바로 고침
.venv\Scripts\python cli.py archive-rows                # 기사 DB 전체 행
```

웹 API로도 같은 일을 할 수 있습니다: `GET /api/archive/rows`(행과 `revision`), `PUT /api/archive/rows`(`{"revision", "rows"}`로 전체 교체), `POST /api/print-check`(`{"folder"}` 또는 `{"names": [파일명...]}`).

## 기사 DB (다른 프로그램에서 읽기)

`database` 폴더에 같은 내용이 세 가지 형식으로 있습니다. "DB 저장"을 누를 때마다 셋 다 갱신됩니다.

| 파일 | 형식 | 이런 데 쓰기 좋음 |
|---|---|---|
| `koita_news.sqlite` | SQLite (원본) | 프로그램에서 조건 검색. 파이썬·엑셀 파워쿼리·DB Browser 등 거의 모든 언어와 도구가 읽음 |
| `koita_news.csv` | CSV (UTF-8) | 엑셀로 바로 열기, 다른 시스템에 올리기 |
| `koita_news.json` | JSON | 웹 화면, 스크립트, 노션 등 API 연동 |

SQLite가 원본이고 CSV·JSON은 저장할 때마다 원본에서 새로 만드는 사본입니다. 그래서 다른 프로그램은 **읽기만** 하고, 기사 추가·수정은 이 프로그램의 "DB 저장"과 "DB 편집" 창으로만 하는 것을 권장합니다(편집 창에서 저장하면 세 파일이 함께 바뀝니다). CSV를 엑셀로 열어 둔 채 저장하면 CSV만 갱신되지 않고 안내가 뜹니다(원본에는 저장됨).

열(SQLite 테이블 `news`, JSON 키 / CSV 머리글):

| 열 | CSV 머리글 | 내용 |
|---|---|---|
| `seq` | 연번 | 게재일시 최신순으로 매긴 번호. 저장할 때마다 다시 매기므로 기사를 가리키는 고정 번호로 쓰지 말 것 |
| `date` | 날짜 | `2026-10-22` 형식. 엑셀 규칙과 같아서 지면 행은 다음 날 |
| `press` | 언론사명 | |
| `type` | 구분 | `온라인`, `방송`, 또는 지면 (`A12면` 등) |
| `title` | 제목 | |
| `url` | URL | 지면 행은 `-` |
| `published_at` | 게재일시 | 온라인 게재 시각 (`2026-10-21T09:00:00+09:00`) |
| `keywords` | 키워드 | 이 기사가 걸린 검색 키워드 |
| `saved_at` | 저장일시 | DB 저장을 누른 시각 |
| `category` | 분류 | 보도자료·특별보도·인용·장영실상·엔지니어상·협력·언급·이슈·정부사업·기타, 고르지 않았으면 빈 값 (v1.3.0~) |

DB는 저장할 때마다 게재일시(published_at) 최신순(같은 기사의 행은 지면 → 방송 → 온라인)으로 다시 정렬됩니다.

중복 판단: 온라인·방송 행은 (URL, 구분), 지면 행은 (날짜, 언론사명, 구분, 제목)이 같으면 같은 행입니다. 단, "DB 저장"으로 넣을 때는 같은 언론사명·제목의 지면 행이 이미 있으면 날짜·지면이 달라도 새로 넣지 않습니다(편집기에서 고친 지면 날짜를 지키려고, v1.3.0~).

다른 폴더(예: 공유 폴더)에 DB를 두려면 `.env`에 `ARCHIVE_DIR=D:\공유\KOITA_DB`처럼 적습니다.

## 새 버전으로 바꿀 때

새 zip을 풀고, 예전 폴더의 `.env`와 `database` 폴더를 새 폴더로 복사하면 됩니다. (`news.db`는 검색 결과 임시 저장소라 옮기지 않아도 됩니다. 옮기면 예전 검색 결과가 그대로 보입니다)

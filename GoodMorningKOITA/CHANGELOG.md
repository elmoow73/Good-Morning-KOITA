## v1.5.0-rc.1 (2026-11-10)

- 보도자료를 고르면 연결 후보: 분류 [보도자료]이고 아직 연결 안 된 기사 중 배포일 -1일 ~ +7일, 제목이 비슷한 순("추천"은 미리 체크). 확인 후 [체크한 기사 연결]. 기사 하나는 보도자료 하나에만
- 보도자료별 연결 기사·건수(온라인·지면·방송 행 각각 1건), 연결 끊기, "미연결 [보도자료] 기사" 탭에서 보도자료를 골라 한꺼번에 연결
- 연결은 기사 DB와 따로 `koita_pressrelease_연도.sqlite·csv·json`(배포일 연도)에 저장, 드롭박스 복사본도. 기사 DB 열은 그대로
- 편집기에서 지면 행 날짜·제목을 고쳐도 연결이 따라감. 지운 기사는 "사라진 기사"로 표시
- **DB 분석** 창에 "보도자료별" (보도자료 수·연결 기사·1건당 평균·미연결 기사·보도자료별 표)
- CLI `press-releases`, `press-release-candidates`, `press-release-link`, `press-release-unlink`, `stats` 결과에 `press_releases`. API `/api/press-releases…`
- 클라우드 백업(`backup.sh`)에 연결표 포함

## v1.4.0 (2026-11-10)

### 실행 방식
- `GoodMorningKOITA.vbs` 더블클릭: 검은 CMD 창 없이 **크롬 탭**으로 열림 (크롬이 켜져 있으면 새 탭, 없으면 새 창. 크롬이 없으면 기본 브라우저). DB 편집·DB 분석도 같은 크롬에서 탭으로
- 프로그램 탭을 모두 닫으면 2분쯤 뒤 프로그램도 종료 (검색·DB 저장 중이면 끝난 뒤). 그래도 꺼지면 열린 탭 위에 "프로그램이 꺼졌습니다…" 안내
- 이미 켜져 있으면 탭만 하나 더, 다른 버전이 켜져 있으면 알림 상자로 알려 줌. 기록은 `goodmorning.log`
- `run.bat`은 CMD 창에서 보는 디버그용 (`run.bat --setup`: 라이브러리 설치만)

### 연도별 기사 DB와 드롭박스 복사본
- 기사 DB 파일 이름을 `koita_news_2026.sqlite/csv/json`으로. 행의 '날짜' 연도로 나뉘고, 2027년 날짜의 행이 처음 저장되면 `koita_news_2027.*`이 새로 생김. 연번은 연도마다 1부터
- 예전 `koita_news.*`는 처음 켤 때 연도별로 나눠 옮기고 `database/_이전`에 백업
- DB 편집 창에 연도 선택(기본 올해). 날짜를 다른 해로 고치면 저장할 때 그 해 DB로 옮김. DB 분석·'저장됨' 표시는 모든 연도 기준. 첫 화면에 "2026년 DB N행"
- `.env` `ARCHIVE_COPY_DIR`: DB가 바뀔 때마다 세 파일을 그 폴더(예: 회사 드롭박스)에 덮어씀 (임시 파일에 쓴 뒤 바꿔치기, SQLite는 backup API). 실패하면 원본은 저장하고 안내만
- CLI `archive-rows --year`, `print-check --year`(기본 모든 연도, 연번은 "2026:12" 형식), API `?year=`. 클라우드 백업(`backup.sh`)도 연도별 파일 모두

### DB 분석 창
- 첫 화면 [DB 분석] 버튼 → 새 창. 기간(전체·올해·작년·이번 달·최근 12개월·날짜 지정)을 고르면 총·온라인·지면·방송 건수와 년도별·월별·분류별·언론사별 표·막대그래프
- DB 행 수 기준 (온라인·지면·방송 행을 각각 1건). 기간은 '날짜' 열 기준
- `GET /api/archive/stats`, `cli.py stats --from --to` (같은 JSON, AI 에이전트용)

### 화면 편의
- 메인 화면 상단바(검색·엑셀 다운로드·DB 저장·체크한 기사 분류·DB 편집·DB 분석)와 기사 표 제목 줄이 스크롤해도 위에 붙어 있음 (틀 고정). 폰처럼 좁은 화면은 제외
- Shift 다중 체크: 한 칸을 누른 뒤 Shift를 누른 채 다른 칸을 누르면 그 사이가 모두 같은 상태(체크/해제)로. 화면에 보이는 순서 기준. DB 편집 창 왼쪽 체크 칸도 같음
- 검색 완료 팝업: "검색이 완료되었습니다 · 새 기사 N건" (검색을 건너뛴 경우는 안 띄움)

### 지면보도 날짜 확인
- 결과의 **파일명을 누르면 지면 기사 파일(JPG 등)이 새 탭에 열림** (`GET /api/print-check/file`, 폴더 밖 파일은 거부. '폴더 직접 고르기'는 브라우저가 고른 파일을 바로 엶)
- **파일 없는 DB 지면 행**에 [파일 찾기]: 같은 매체이거나 날짜 앞뒤 3일 안의 파일을 후보로, 파일명 눌러 확인, [이 파일과 연결]
- **DB에 없음** 파일에 [지면 파일 삭제]: 확인 창을 거쳐 지면 폴더 안 `_삭제한 파일`로 옮김 (완전히 지우지 않음, 비교에서 빠짐. PC 폴더로 비교할 때만). `POST /api/print-check/trash`
- **게재일시 다름** 탭: 게재일시 날짜가 지면 날짜와 다른 지면 행을 보여 주고, 체크한 것만 지면 날짜 00:00으로 반영 (저장해야 DB에 들어감). CLI `print-check` 결과 `published_diff`, `--fix-published`

### 기본 키워드
- `"한국산업기술진흥협회"` 뺌 (`"산업기술진흥협회"`가 함께 찾음), `"기술개발인"`, `"구자균"` 추가. 이미 쓰던 `news.db`에도 처음 실행할 때 한 번 반영 (직접 추가한 키워드는 그대로)

- 클라우드 서버용 설정 (모두 선택, 비우면 예전과 같음): `DATA_DIR`, `HOST`·`PORT`, `OPEN_BROWSER`, `SESSION_SECRET`
- `GET /healthz`: 로그인 없이 부르는 상태 확인 JSON (문제 있으면 503)
- `Dockerfile`(크로미움·한글 글꼴, 데이터 `/data`), `deploy/`(Oracle Cloud 설치·업데이트 `setup.sh`, 구글 드라이브 백업 `backup.sh`, Caddy HTTPS)
- 폰 화면에서 기사 표 가로 스크롤, 긴 오류 문구 줄바꿈

### 분류
- 기사 목록 키워드 오른쪽에 **분류** 드롭다운: 선택(기본) / 보도자료 / 특별보도 / 인용 / 장영실상 / 엔지니어상 / 협력 / 언급 / 이슈 / 정부사업 / 기타
- 기사 여러 개를 체크한 뒤 "체크한 기사 분류"로 한 번에 고르기 ("선택으로 되돌리기" 포함)
- DB 저장을 누르면 기사 DB 맨 오른쪽 `category`(분류) 열에 저장. 이미 있는 행도 새로 고른 분류로 덮어씀("선택"이면 예전 값 유지)
- 기존 기사 DB·`news.db`에는 처음 켤 때 분류 열이 자동으로 더해짐 (열 추가만이라 다른 프로그램과 호환)

### DB 편집 창 (`/editor`, 위쪽 "DB 편집" 버튼)
- 기사 DB를 엑셀처럼 직접 고치기: 방향키·Enter 이동, 엑셀 여러 칸 붙여넣기, 열 정렬, 찾기·구분 골라 보기, 행 추가·삭제, 고친 칸 노란색, Ctrl+S 저장
- 왼쪽 칸을 체크한 행들의 분류를 "체크한 행 분류" 목록으로 한 번에 바꾸기
- URL 칸 오른쪽 ↗를 누르면 기사가 새 탭으로 열림 (칸을 누르면 고치기). 제목 옆에 버전 표시
- 저장하면 SQLite를 바꾸고 CSV·JSON도 같은 내용으로 다시 만듦. 날짜·URL 형식, 빈 칸, 중복 행을 검사해 문제 칸을 빨갛게 표시. 편집 중 다른 곳에서 DB가 바뀌었으면 덮어쓰지 않음
- **붙여넣어 가져오기**: 예전 DB를 엑셀에서 머리글 행까지 복사하거나 CSV 파일을 열면 머리글 이름으로 열을 맞춰 새 행으로 넣음. 미리보기에서 추가할 행 / 이미 있음 / 형식 오류를 나눠 보여 줌. 게재일시가 없으면 날짜 0시, 키워드·분류가 없으면 빈 값

### 지면보도 날짜 확인 (편집 창 버튼)
- 지면 기사 폴더(`.env` `NEWSPAPER_DIR`, 하위 폴더 포함)의 파일명 `[매체명] 기사제목_지면_날짜.jpg`와 DB 지면 행을 매체명·제목으로 짝짓고 날짜·지면을 비교. 지면은 숫자만 비교(`인물 29면` = `A29면`)
- 결과: 일치 / 틀림(파일 값 ↔ DB 값) / **일치 의심**(제목이 달라도 매체가 같고 날짜 ±1일·제목 낱말이 비슷하면, 이유와 함께) / 파일명 오류(어느 칸인지) / DB에 없음 / 중복 파일 / 파일 없는 DB 지면 행
- 고칠 항목을 체크해 표에 반영 → 저장. 일치 의심은 처음에 체크하지 않음
- **DB 기사와 연결**(지면 행이면 그 행과 비교, 온라인·방송 행이면 지면 행을 새로 만들어 연결, `database/print_links.json`에 기억), **새로 등록**(파일명으로 새 지면 행), **연결 끊기**
- **DB 제목을 지면 제목으로**: 일치 의심·연결 항목의 DB 지면 행 제목을 지면 기사 제목으로 바꿈(온라인 행은 그대로). 기록(`database/title_aliases.json`)을 남겨 같은 기사를 다시 DB 저장해도 지면 행이 또 생기지 않음
- 폰·클라우드 서버에서는 "폴더 직접 고르기"로 파일명만 보내 비교

### DB 저장 규칙
- 같은 언론사·제목의 지면 행이 이미 있으면 날짜·지면 번호가 달라도 새로 넣지 않음 (편집 창에서 고친 날짜를 지키려고. 온라인·방송 행은 예전처럼 URL 기준)

### 화면 없이 실행·API (AI 에이전트용)
- `cli.py`: `print-check [--folder] [--apply]`, `archive-rows` (JSON 출력, 종료 코드 0/1/2)
- API: `GET/PUT /api/archive/rows`, `POST /api/print-check`, `POST /api/print-check/link`, `POST /api/archive/title-alias`, `POST /api/articles/category`, `PATCH /api/articles/{id}`의 `category`
